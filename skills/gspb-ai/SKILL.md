# gspb-ai: 规培轮转手册补录

用于自动化补齐医院教培系统规培轮转手册的病种与操作缺口。基于 `ego-browser` 驱动真实浏览器，保证安全登录、时间合规、全量预审与零误触。

## 核心 Agent 契约（唯一执行路径）

1. **环境自动代劳**：在执行前若检测到缺少 `ego-browser` 命令，Agent **必须直接在后台运行 `./install.sh`**（脚本会自动从高速 CDN 下载、挂载并配置好 ego lite 运行底座），**严禁**将下载链接抛给用户让小白医生自行手动操作。
2. **时间窗过滤与科室保护（临床合规底线）**：
   - 当用户说「帮我补录轮转手册」且未指定科室时，直接执行 `bin/gspb plan`（不传 `--dept`）；
   - 系统会自动以当天日期为准，**严格剔除尚未开始轮转的未来科室（`start > today`）**，优先锁定当前正在轮转的科室，并列出已出科待补录的历史科室；
   - 若用户指定的科室属于尚未轮转的未来科室，系统将直接报错阻断，**严禁**为未轮转科室提前录入任何虚假数据。
3. **引导登录**：首步执行 `bin/gspb login`。若输出包含 `需要你先在浏览器里登录`，必须把该文本块**完整转述**给用户，并停下等待用户回复「已登录」；**不得**猜测、代填或索要账号密码。
4. **先计划后执行，审阅门禁**：执行 `bin/gspb plan` 后，必须把输出的**配额汇总表、全部明细行及文件路径完整原样粘贴到对话中**。粘贴完毕后停下等待用户明确回复 `yes` / `确认`。用户未明确放行前，**严禁**执行任何 `fill` 命令。
5. **受控消费与断点续填**：用户放行后执行 `bin/gspb fill --plan <plan.json 绝对路径>`。每 10 条播报一次进度；全部完成后执行 `bin/gspb verify` 并粘贴复查对账表。

## 禁区按钮与安全边界

- **禁区按钮**：全程只点击文字为 `手动录入`、`提交`、`退出` 的按钮。**绝不触碰** `撤回`、`提交审批`、`删除`。
- **停止条件**：遇以下情况立即中止并向用户报告：
  - 用户要求停止；
  - 连续失败 ≥ 3 次；
  - 表单提交后该行实际完成例数未增加；
  - 页面掉落回 `#/login`。
- **数据留痕**：计划与历史断点保存在 `~/.cache/gspb-AI/<工号>/<记录id>/`，支持中断后断点续填。
- **号段安全**：仅使用 18 经验号段加权随机模型，杜绝单调序列与真实患者号码碰撞；可选用户本地黑名单置于 `~/.config/gspb-AI/blacklist.csv`。

## CLI 常用命令

```bash
# 1. 检查或引导登录
bin/gspb login

# 2. 自动识别正在轮转科室并生成预审计划（排除未来科室）
bin/gspb plan

# 3. 指定历史待补录科室生成计划
bin/gspb plan --dept 儿牙

# 4. 执行受控补录（必须提供已审阅 plan.json）
bin/gspb fill --plan ~/.cache/gspb-AI/G1096/00h9m3k3xp51anyucskjjpg9j/plan.json

# 5. 复核达标状态
bin/gspb verify --dept 口腔修复科
```
